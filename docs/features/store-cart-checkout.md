# Корзина и оформление заказа

Глобальная корзина менеджера и страница оформления `/store/checkout`: раскладка на черновики заказов клиента по способу **Склад региона** или **Производственная площадка**.

## Зависимости

- Контекст региона (`useSelectedRegion`, `RegionProvider` в корневом layout) — [store-pim-catalog.md](store-pim-catalog.md).
- Запасы «Готово · Всего» — тот же `computeVariantRegionStock`.
- Деньги заказа / floatrates — [logistics.md](logistics.md).

## Корзина

- Хранение: `localStorage` ключ `store-cart` = `[{variantId, quantity}]`, синхронизация между вкладками.
- Количество кратно `quantity_per_unit` (ввод округляется вверх; ≤0 удаляет строку).
- Кнопка в футере nav rail (над Settings) открывает шторку справа; «Оформить» → `/store/checkout`.
- В каталоге и на карточке товара тележка добавляет одну упаковку и превращается в счётчик `− N +`.

Файлы: `src/features/store/cart/*`.

## Оформление

Страница: `app/store/checkout/page.tsx` → `StoreCheckoutPage`.

Две карточки способа:

| Способ | Блоки | Цена | Источник заказа |
|--------|-------|------|-----------------|
| Склад региона | один блок = хаб региона | дилерская × (1 + расходы на поставку %/100), до копеек; нет % → 0% | `hub` + `store_region.hub_warehouse_id` |
| Производственная площадка | блок на каждую площадку (код) | дилерская без наценки, до копеек | `plant` + `plant_id` |

- Галочка строки → снятые уходят в свёрнутый «Остаются в корзине».
- У хаба при нехватке: подпись «N из наличия · M под заказ»; наценка на всё количество.
- Площадки/склады — только коды (префиксы из «Settings → Префиксы кодов», по умолчанию `PLT-n`, `WH-n`); слово «завод» не используется.
- Калькулятор контейнеров — в каждом блоке площадки: мультиселект типов, движок `packMixedContainers` (сначала меньше контейнеров — один 40ft лучше двух 20ft; при равном числе — меньше пустого объёма), 3D-сцена с кодом типа и % заполнения. Негабарит — предупреждение, оформление не блокируется. Компонент общий с карточкой заказа клиента (вкладка «Контейнеры»): `src/features/store/packing/container-load-calculator.tsx`.
- «Оформить подзаказ» (у блока площадки, если площадок несколько) / «Оформить заказ» (одна площадка — кнопка только у блока) / «Оформить всё» (хаб или несколько площадок — кнопка в подвале). У одного блока кнопка одна. RPC `store_checkout_customer_order` создаёт черновик `draft` (открытый заказ: план и действия доступны сразу). Валюта денег — `store_region.order_currency_id` (иначе дилерская).
- В режиме «Склад региона» блок один, потому что хаб региона один: товары с разных площадок едут одним заказом. Кнопки у блока нет — только «Оформить всё». Чужой склад RPC не принимает: «Склад не относится к региону». Неактивный регион тоже отклоняется.
- Цена строки считается на сервере в момент оформления: дилерская цена региона, для хаба плюс расходы на поставку. Цена из браузера игнорируется. Нет дилерской цены или статус не `available` — ошибка блока. Суммы строк и итоги на экране округляются до копеек.
- Курсы, по которым посчитана примерная сумма (плавающие или запасные из справочника), пишутся только в `store_order_money.rates` этого заказа. Справочник `store_currency` не меняется. То же для `store_create_customer_order` и `store_create_production_order`.
- Повтор той же отправки после ошибки или потерянного ответа, пока страница оформления открыта, передаёт тот же `checkout_key` — идентификатор попытки, не состав корзины — и получает уже созданный заказ, без второго черновика. Перезагрузка начинает новую попытку. После успеха попытка забывается: такой же заказ позже создаётся заново. Пока блок оформляется, количество и галочки в нём недоступны. Из корзины вычитается отправленное количество: то, что добавили в другой вкладке, остаётся.
- Удалённый или архивный вариант — строка «Товар удалён» и кнопка «Убрать» (и в шторке, и на оформлении). У заблокированных строк остатка тоже есть «Убрать». Нечисловой id в `localStorage` отбрасывается, остальная корзина грузится. Сбой загрузки каталога — баннер с «Повторить». Пока остатки не загрузились, разбивка «из наличия / под заказ» не показывается.
- Созданные строки уходят из корзины на отправленное количество; окно результата — со ссылками и ошибками.

## Данные

Миграции:

- `store_product_variant_logistics`, `store_container_type`, `store_product_supply_cost`
- `store_product_variant.quantity_per_unit`, `store_region.order_currency_id`
- `store_customer_order.checkout_key` — идемпотентность оформления; курсы заказа в `store_order_money.rates`
- сид из `scripts/data/logistics-demo.json` через `scripts/generate-cart-checkout-seed.mjs`

Диалог региона (логистика): поле **Валюта заказов**.
