## Intent

**Problem:** Карточки документов Store (заказ клиента, заказ на производство, перемещение, отгрузка/возврат, выпуск, резерв, корректировка) собраны по-разному и выглядят неряшливо: шапка разбита на 3–4 карточки, есть бесполезный блок «Где лежит <товар>», у перемещения «История документа» висит справа и не универсальна, таблица товаров заказа клиента визуально тяжёлая, остатки выглядят плоско (и пишут `pcs`). Ни в одном документе не видно истории статусов и даты завершения. Меню Store — три безымянные группы.

**Approach:** Один современный премиальный каркас карточки по макету `store-documents.html`: шапка-паспорт (тип, номер, статус, мета-поля с ключевыми датами, действия) и вкладки разделов «Товары / … / Движения / История». Все семь карточек переходят на каркас с сохранением поведения, добавляется универсальная вкладка «История», меню группируется по процессам, «Остатки» получают визуальное обновление, демо-история перезасевается с правдоподобными датами.

**Decisions (2026-09-23):**
- Только карточки документов, меню и страница «Остатки»; списки документов не трогаем. Заказ на производство тоже переходит на каркас.
- Мета-поля шапки: все значения — одна строка одинаковой высоты (32px) на общей линии независимо от вида (код, пилюля, текст, редактируемое поле). Редактируемые значения (статус, ожидаемое окончание) выглядят как текст с иконкой и подсвечиваются полем при наведении/фокусе; сущность «Тип + код» — в одну строку; просрочка — янтарная пометка «−N дн.» с подсказкой. Подписи полей не переносятся.
- Документы в этапах хода заказа (решение 2026-09-23, 15:33) — компактный список в одной рамке с разделителями, одна строка на документ: код, пояснение («35% заказа», «2 шт · до 25.09»), справа статус только у документов со статусным циклом; у проведённых (резервы, отгрузки, возвраты) статуса нет, подпись этапа «N проведено».
- Разделы документа — вкладки (везде, на любой ширине), не левое оглавление. Выбранная вкладка хранится в hash адреса; строка вкладок скроллится по горизонтали. Внутри вкладки заголовок раздела не дублируется, над таблицей только строка действий.
- Меню: Каталог (Товары, Прайс-листы) · Продажи (Заказы клиента, Отгрузки и возвраты, Резервы) · Производство (Заказы на производство, Выпуски) · Склад (Остатки, Перемещения, Корректировки, Журнал) · Справочники (Склады, Регионы, Заводы) · без заголовка (Импорт/Экспорт, Настройки). Пункты с иконками.
- Заказ клиента: полоса этапов «Производство → Выпуски → Перемещения → Отгрузки» — отдельная карточка под шапкой; строка «Связанные» с кнопкой «Показать/Скрыть», которая раскрывает этапы «Резервы» и «Возвраты» с документами и действиями. Колонки таблицы товаров те же; группы «Поток» / «Резерв на складах» — одна подпись без второго подчёркивания; «Отгружено N из M» + мини-прогресс; выполнено — галочка, без заливки строки.
- Действия строки в таблицах товаров (решение 2026-09-23, 14:39): кнопка «⋯» — справа внутри ячейки «Товар», видна при наведении на строку, при фокусе внутри строки и пока меню открыто; отдельной колонки действий нет. Двухэтажные заголовки таблиц: все подписи на одной базовой линии (ячейки прижаты к низу, коды складов в заголовке — ссылки без рамки).
- «Где лежит» удаляется полностью, без замены. Из строк резерва убирается комментарий, из строк корректировки — пояснение (оно в описании документа).
- «Движения»: без кнопки «Открыть в журнале».
- «История»: без полосы итоговых дат (они в шапке). Одна запись = один снимок истории; каждое поле, отличающееся от предыдущего снимка, — строка «было → стало»; статус и дата, изменённые одновременно, — одна запись «Изменены статус и ожидаемое окончание» с двумя строками.
- Заказ на производство: резервы товара — прежняя компоновка текущего `ProductionOrderProductManifest`: под товаром приглушённые строки разбивки (каждый владелец резерва, «Свободно», «Выпущено»), выровненные по колонкам «План / Свободно / В резерве / Выпущено»; меняется только стиль. Выпуски: колонка «Закреплено за» — заказ клиента, регион или «Свободно» (по `toOwnerType` строк); колонка «Завершён».
- Перемещение: мета-поля «Откуда», «Куда», «Сейчас», «Ожидалось», «Отправлено», «Доставлено»; дата-время одной строкой. «Товары и резервы» — таблица «Закреплено за / Товар / Количество»; переключатель группировки объединяет строки владельца в одну ячейку с «Итого».
- Остатки: цвета колонок «Закреплено за» совпадают с полосой распределения в новой колонке «Всего» (свободно — нейтральный, резерв региона — светло-синий, резерв заказа — синий); единицы через `formatQuantity`.
- Код товара (решение 2026-09-23, 14:20): везде в Store — документы, таблицы, формы, выбор товара в диалогах, PIM, прайс-листы — идентификатор товара только `PRD-N` (`formatLogisticsCode`). Поле SKU (`FX-350-ULTRA` и т.п.) сносится полностью: колонка `store_product_variant.sku` и её уникальный индекс удаляются миграцией, `store_create_product_variant` без `p_sku`, read-RPC и клиент без SKU; поиск «по названию или коду»; поле «Артикул» убирается из формы создания товара и из PIM. Демо-значения SKU теряются — согласовано.
- Типографика (решение 2026-09-23, 14:23): единая шкала из трёх размеров Tailwind — `text-2xl` только номер документа; `text-sm` основной текст (значения шапки, ячейки таблиц, вкладки, кнопки, заголовки записей истории, пункты меню); `text-xs` вспомогательный (подписи полей, заголовки и группы колонок, счётчики, время/автор, пояснения, коды-бейджи). Иерархия — весом и цветом. Произвольные `text-[…px]` в карточках документов, меню Store и «Остатках» запрещены.
- Демо-история: поправить сид и перезасеять демо-БД, чтобы `changed_at` шли правдоподобно от `created_at` документа; текущие демо-записи пересоздаются.

## Boundaries & Constraints

**Always:** Все существующие действия, диалоги, проверки доступности и тексты отмены работают как раньше (те же API-функции и формы). Коды мест вместо названий (`place-codes.md`). Полная ширина, без `max-w-*`. Статус никогда не передаётся только цветом. Русские подписи. Одна загрузка данных на страницу (`useLogisticsStore` как сейчас). Ноль в таблицах — как в текущих таблицах, `—` — неприменимо.

**Never:** Не менять RPC записи, схему БД и триггеры, кроме сноса SKU по решению выше (сид может временно отключать триггер иммутабельности истории внутри своей транзакции). Не менять списки документов. Не вводить новую палитру/шрифт вне токенов shadcn (тонированные статусные пилюли на Tailwind-палитре допустимы). Не ломать `ModuleSubnav` для других модулей. Не оставлять мёртвые `AvailabilityPanel`, `TransferActivity`, `ProductionOrderSectionIndex`.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Документ с циклом | заказ/перемещение/выпуск с `documentHistory` | первая запись «Создан» со статусом; далее по снимку на запись со строками изменений; автор из `users` | нет автора → «—» |
| Одновременная смена | снимок отличается статусом и датой | одна запись, две строки изменений | — |
| Документ без цикла | отгрузка, корректировка | одна запись «Создан и проведён» (`createdAt`) | — |
| Резерв | `postedAt` null / задан | «Создан»; если проведён — «Проведён» (`postedAt`) | — |
| Нет истории | lifecycle-документ без снимков | одна запись «Создан» из `createdAt` | — |
| «Завершён» в шапке | первый снимок со статусом `done` | его `changedAt`; иначе «—» | — |
| Hash вкладки | `#movements` при загрузке | открыта вкладка «Движения» | неизвестный hash → первая вкладка |

**Acceptance Criteria:**
- Given любая из семи карточек, when открыта, then шапка — одна панель с типом, номером, статусом, мета-полями и действиями; ниже вкладки со счётчиками, последняя — «История».
- Given любое действие карточки до изменений (резерв, снятие, отгрузка, выпуск, закрытие, смена статуса/даты, отмена с подсказками, обратное перемещение, провести резерв, добавить строку/товар), when выполнено, then результат тот же, что до редизайна.
- Given отгрузка, выпуск, резерв или корректировка, when открыта, then блока «Где лежит» и раскрытия наличия нет.
- Given боковое меню Store, when открыто, then пункты разложены по группам решения, активный пункт подсвечен.
- Given страница «Остатки», when открыта, then нет `pcs`, числа совпадают с текущими, «Всего» = сумма колонок «Место».
- Given перезасеянная демо-БД, when открыть историю заказа клиента, then даты записей не раньше «Создан» и идут по возрастанию.
- Given любой документ, форма, диалог выбора товара, PIM или прайс-лист, when показан товар, then его код — `PRD-N`, и нигде нет значений вида `FX-350-ULTRA` или подписи «Артикул».

## Design Notes

Визуальный контракт — `store-documents.html` (переключатель экранов сверху, у каждого — список изменений; hash `#co:history` открывает вкладку). Премиальность — геометрия и типографика: номер 26px semibold с отрицательным трекингом, мета-поля с тонкими вертикальными разделителями, заголовки таблиц 11–12px muted без заливки, числа `tabular-nums` вправо, мягкие тени карточек, тонированные статусные пилюли с точкой, вкладки с подчёркиванием и счётчиком. `DESIGN.md` 2026-09-21 заменяется этим макетом в части «не вкладки» и «без цвета статусов».

История документов без цикла синтезируется на клиенте без изменений БД. Реализация — по задачам по очереди; технические задачи делегируются субагентам и проверяются (typecheck, сверка с макетом).
