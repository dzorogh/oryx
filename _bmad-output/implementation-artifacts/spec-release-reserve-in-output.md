## Intent

**Problem:** Резерв под заказ клиента в черновике выпуска можно снять только отменой всего выпуска, хотя для складских резервов снятие — обычная операция «другим резервом» в обратную сторону.

**Approach:** Одна операция перераспределения внутри черновика выпуска: количество переносится между строками владельцев (свободно → заказ клиента = резерв, заказ клиента → свободно = снятие). Действие «Снять» доступно в меню строки заказа клиента (рядом со снятием складских резервов) и в строке резерва выпуска на вкладке «Товары» заказа на производство; диалог с количеством, по умолчанию — весь резерв. Только для выпусков в статусе черновик.

</frozen-after-approval>

## Implementation Notes

- Миграция `20260923213000_store_move_in_production_output.sql` (применена к demo Supabase через `execute_sql`, чтобы не плодить дубль файла): общий `store_move_in_production_output(output, from_owner, to_owner, lines)`; `store_reserve_in_production_output` стал обёрткой «свободно → владелец».
- Клиент: `releaseInProductionOutput` в `logistics-api.ts`, хелпер `draftOutputHoldsForOrderProduct` + тест, общий диалог `ui/output-release-dialog.tsx`; подключён в меню строки заказа клиента и в строке резерва выпуска на вкладке «Товары» заказа на производство.
- Проверено: probe с rollback (снятие, повторное снятие отклонено, повторный резерв); в браузере реальное снятие в OUT-919 через PO-925 с тостом, затем резерв возвращён SQL и подтверждён (1 шт под OMS-906); пункт меню «Снять в выпуске OUT-919 · 1» на OMS-906. `typecheck`, `npm test` 104/104, eslint по изменённым файлам, `build`.
