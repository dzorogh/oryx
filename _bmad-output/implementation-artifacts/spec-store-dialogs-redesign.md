## Intent

**Problem:** Диалоги логистики выглядят и ведут себя по-разному: товары добавляются селектами «выберите товар», строки резерва — мини-формы, поля блокируются без объяснения, ограничение ввода не видно рядом с полем, после создания окно просто закрывается.

**Approach:** Все диалоги переводятся на четыре типа по намерению брейншторма (§2–§4) и макетам `.working/key-*.html`: A — каталожная модалка ~90vh (дерево «категория → товар → подстроки владельцев»), B — строки контекста (как «Запустить производство»), C — компактная форма, D — подтверждение. Общая оболочка, общий компонент каталожной таблицы, единые правила ввода, отправки и закрытия.

## Boundaries & Constraints

**Always:**
- Оболочка: надзаголовок + заголовок; белая шапка с реквизитами документа полями с подписями сверху; для типа A — отдельная серая панель «Товары» (поиск, «Свернуть все», «Только выбранные», контролы 28 px, кнопки без обводки); тело скроллится; липкий футер с живым итогом и кнопкой-глаголом.
- Тип A: у каждого товара подстроки владельцев, даже при одном владельце; поле количества только в подстроке; без счётчика «N владельцев»; разделители между товаром и подстрокой; категории липкие, раскрыты только с введёнными значениями или совпадением поиска; пустые подстроки бледнеют.
- Жёсткое ограничение: ввод не урезается, поле красное, «максимум N». Мягкое (заказ клиента): нейтральная «сверх остатка N».
- Кнопка отправки не блокируется из-за ошибок: клик показывает ошибки и фокусирует первую; выключена только при нуле строк с причиной в футере; во время запроса «Создаём…» и блок.
- Esc / клик мимо при введённых данных — «Закрыть без сохранения?». Ошибка сервера — внутри окна над футером, ввод сохраняется.
- После создания документа — открыть его; несколько документов — главный + ссылки в тосте; изменение текущего документа — остаться и подсветить строки.
- Автофокус в первое поле; Enter в количестве — следующее поле; Cmd/Ctrl+Enter — отправка (подписано в футере); количество `type="text" inputMode="decimal"`.
- Склады и заводы — только коды (кроме своих справочников). Весь текст — по-русски. Не повторять подписью то, что видно из полей и структуры.
- Мобильный: A и B на весь экран, D компактный.

**Решения пользователя (25.09):**
- Новый PO / добавить в PO: две колонки-подсказки «На складе завода» и «Уже производится» (открытые выпуски и незакрытый план PO этого завода по товару).
- Тип склада вместо флага хаба: `plant` (склад завода), `hub` (склад-хаб), `customer` (склад покупателя). Склад, привязанный к заводу, — `plant`, тип не редактируется; остальные выбираются в карточке склада. В демо-данных хаб — только Dubai Hub; прочие склады без завода — `customer`. Источник «Хаб» в заказе клиента предлагает только склады типа `hub`.
- Источник заказа клиента хранится в заказе и показывается в шапке заказа («С завода PLT-N» / «С хаба WH-N»). План исполнения по источнику не предзаполняется и отдельно не ограничивается: при источнике-заводе в заказе и так только товары этого завода; при хабе ограничений по заводу нет.
- Миграция применяется к демо-базе `oryx-supabase`.

**Never:** прайс-листы PIM, шторки фильтров и колонок; кнопки массового заполнения («Заполнить всем остатком», «Взять всё под CO-N»); отдельная колонка «Владелец»; селект товара вместо строк; заблокированные поля без пунктирной заглушки с причиной.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Перемещение из списка | склад-источник не выбран | вместо таблицы пунктир «Выберите склад-источник, чтобы увидеть остаток» | — |
| Перемещение из заказа CO-N | открыто с заказа | видны только подстроки CO-N; переключатель «Показать весь остаток склада» | — |
| Ввод сверх остатка владельца | 30 при остатке 18 | поле красное, «максимум 18», значение не меняется | отправка фокусирует поле |
| Заказ клиента с хаба сверх остатка | 4 при 2 на хабе | «сверх остатка 2», не ошибка | — |
| Смена источника заказа | товары не выпускаются новым заводом | баннер «N товаров PLT-N не выпускает — будут убраны» + подтверждение | отмена возвращает прежний источник |
| Двойной клик по отправке | запрос идёт | вторая отправка не уходит | — |
| Ошибка RPC | сервер отклонил | текст ошибки над футером, окно открыто | `translateLogisticsError` |
| Закрытие с данными | Esc | «Закрыть без сохранения?» | — |

**Acceptance Criteria:**
- Given любое окно, двигающее товар, when оно открыто, then товары вводятся в строках таблицы, а не селектом, и ограничивающее число стоит рядом с полем.
- Given создан документ, when запрос успешен, then открывается страница этого документа.
- Given изменён текущий документ (резерв/снятие в выпуске), when запрос успешен, then окно закрыто, изменённые строки подсвечены.
- Given запланированный выпуск, when нажать «Добавить товары», then открывается окно B со строками незанятого плана PO и лимитом «осталось по плану».
