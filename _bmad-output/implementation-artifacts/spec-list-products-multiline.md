## Intent

**Problem:** В списках логистики товары склеиваются в одну строку через запятую и без количества, поэтому длинные документы (например OMS-906 с 20 SKU) нельзя прочитать.

**Approach:** Показывать каждую позицию с количеством на своей строке, максимум 5 видимых, остальные раскрывать по «Ещё N». Тот же вид во всех списках документов, где есть колонка товаров.

</frozen-after-approval>

## Implementation Notes

- Общий компонент `DocumentProductLines`: одна строка = название-ссылка + `formatQuantity`, превью 5, кнопка «Ещё N» / «Свернуть». Состояние раскрытия локальное, не пишется в URL.
- Подключено в списках: заказы на производство, заказы клиента, перемещения, отгрузки, возвраты, выпуски; на карточке PO — таблица выпусков. Резервы оставили построчный rowspan, но тот же лимит 5 и общая кнопка.
- Списки отгрузок/возвратов/выпусков раньше не показывали товары — добавил колонку, чтобы «другие списки» выглядели так же.
- Тесты: `document-product-lines.test.tsx`, `reservation-hold-list.test.tsx`. Пустая таблица заказов клиента: assertion на «Пока нет записей.»
- Браузер: PO-906 «Ещё 3» раскрывает GP 401/881/1100 Ultra; OMS-906 показывает 5 строк + «Ещё 15»; перемещения и отгрузки — имя + количество.
- Коммит не делал: в дереве уже много чужих незакоммиченных правок, пользователь коммит не просил.
- После review: «Ещё» в резервах на `colSpan={2}`; имена с `break-words`; список + `aria-controls`; заголовок выпусков на карточке PO — «Товары»; тест на ровно 5 строк.
