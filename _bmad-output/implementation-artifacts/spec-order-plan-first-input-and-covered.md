## Intent

**Problem:** На вкладке «План» без планов показывается пустое состояние с кнопкой; у полностью обеспеченных товаров видны неактивные поля «Взять»; «N лишнее» в панели «План» считает товары, где резерв сверх заказа был ещё до плана (в плане их нет), и из-за этого нельзя запустить; шапка карточки товара крупнее шапок «Товары» и «План».

**Approach:** Без планов сразу открыть черновик «План 1», который создаётся в БД при первом вводе. Обеспеченные товары без действий плана не предлагать к планированию. Лишнее — только то, что добавил план (в UI и в `store_launch_order_plan`). Шапку карточки товара привести к размеру шапок соседних панелей.

## Boundaries & Constraints

**Always:** Русский текст, коды WH/PLT. Браузер пишет только через RPC. Товар с действиями плана остаётся редактируемым (чтобы можно было уменьшить). Уже существующее превышение резерва над заказом не блокирует запуск и не называется «лишним».

**Decisions (человек):** Обеспеченные товары без действий плана уходят вниз списка «Товары» в группу «Обеспечено N»; в карточке такого товара вместо разделов «Взять» / «Заказать дополнительно» — строка «Товар обеспечен».

**Never:** Не менять кнопку «Новый план» при уже существующих планах; не создавать план при простом открытии вкладки; не удалять план пользователя из демо-базы; не трогать сид.

| Резерв сверх заказа до плана | have > ordered, действий нет | «Осталось 0», не янтарный, не в «лишнее», запуск доступен | — |
| План добавил лишнее | have + plan > ordered, plan > 0 | янтарное «Осталось −k», k = min(plan, have + plan − ordered) | запуск отклоняется |

## Implementation Notes

- Черновик без плана: `unsaved = !plan && canAct`; первый `setAction` в очереди вызывает `store_create_order_plan`, сразу кладёт payload и `?plan=`, затем пишет действие. Ключ карточки товара — `draft`, пока план не создан или только что создан этим вводом (ввод коммитится с задержкой прямо во время набора).
- `ProductPlan.excess` = min(план, уже есть + план − заказано); `remaining` для показа не ниже −excess; `isCovered` = уже есть ≥ заказано и в плане по товару ничего нет.
- Миграция `20260924190000_store_order_plan_excess_from_plan.sql` применена к демо-базе. Пробные планы на OMS-2 удалены SQL в той же сессии.
- `npm test`: 2 падения, `npm run lint`: 7 проблем, `check:deps`: расхождение версий — всё то же на базовом коммите, изменением не вызвано.
