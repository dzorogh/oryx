## Объём

План только **резервирует под этот заказ** и **заказывает производство**. Действий со своим резервом (переместить, отгрузить, снять) в плане нет — они остаются прямыми кнопками на карточке. `kind` действия: `reserve` | `produce`.

### База

- Таблицы `store_order_plan`, `store_order_plan_action` по постановке (без `to_location_id`; уникальный ключ `(plan_id, kind, product_variant_id, location_id, owner_id, plant_id)`).
- Место выпуска: все пункты «Изменения в базе» из `output-stock-location.md`.
- `store_place_available(variant, location, owner)` — одна функция для чтения, проверки ввода и запуска.
- Команды: `store_create_order_plan` (в том числе копией), `store_rename_order_plan`, `store_set_order_plan_archived`, `store_set_order_plan_action` (ноль удаляет; увеличить — только в пределах доступного и непокрытого остатка строки заказа; уменьшить — всегда), `store_launch_order_plan`.
- Запуск — одна транзакция: блокировки и перепроверка → резервы на складе и в пути → резервы в черновиках выпусков и новые черновики выпусков из незанятого плана PO → докинуть в PO и новые PO (статус «Черновик», один на завод) с черновиками выпусков под заказ. Внутри вызывать существующие команды документов. Любой минус или лишнее — откат всего. `result_document_id` заполняется у каждого действия.
- Чтение — частью `store_document_context` заказа клиента: планы, действия, строки источников по товарам заказа (место × владелец × доступно). Один запрос на страницу.
- Браузер не пишет таблицы напрямую — только RPC.
- Раздел постановки «Делает пользователь» (увеличение строки PO, докинуть в закрытый PO, удаление `in_progress` у выпуска), судя по миграциям `20260924170000_store_output_status_planned_done.sql`, `20260924171000_store_editable_order_lines.sql`, `20260924172000_store_order_lines_fixups.sql`, уже сделан. Проверь и опирайся на это; не переделывай.
- Новые миграции — в `supabase/migrations/` с таймстемпом после последней; применить к `oryx-supabase` через MCP. Демо-данные: у 2–3 открытых заказов клиента — правдоподобные планы (черновик, запущенный, архивный). Никаких TEST/dummy-строк; диагностические записи удалить в той же сессии.

### Интерфейс

Новая вкладка «План» в `DocumentTabs` карточки заказа клиента (`src/features/logistics/customer-orders-page.tsx`), между «Товары» и «Документы». Отдельной страницы нет. Код фичи — рядом, в `src/features/logistics/` (например `order-plan/`), shadcn-компоненты проекта.

Раскладка (см. макет A3):

1. **Строка плана** — отдельная тонкая карточка над тремя блоками: кнопка выбора плана (имя + чип состояния «Черновик» / «Запущен 22.09 14:10» / «Архив» + стрелка), приглушённое «создан 24.09», меню «⋯» (Переименовать, Копировать в новый черновик, В архив / Вернуть из архива), справа «+ Новый план». Список планов: имя, дата, чип, галочка у текущего; архив — под разделителем с «Вернуть». Открывается последний созданный план.
2. **Три блока** на всю ширину:
   - **Товары** (узкий, ~288px): название, цвет второй строкой, «20 / 20», тонкая полоса (сплошная — уже есть, штриховка — в плане, контур — не покрыто; минус и лишнее — за краем полосы красным/янтарным), точка проблемы. Выбранный подсвечен.
   - **Выбранный товар** (гибкий): четыре числа «Заказано · Уже есть · В плане · Осталось» и полоса по видам места (склад / в пути / выпуск). Раздел **«Взять»**: группы «Склад», «В пути», «Выпуск» (черновики выпусков), «Заказано на производстве» (незанятый план PO, пунктирный квадратик); строка — код места (жирный) + мелкий контекст (WH-1 → WH-3, PLT-2) + чип владельца («свободно» нейтральный; чужой заказ / регион приглушённый, ниже свободных) + «Доступно» + поле «Взять». Раздел **«Заказать дополнительно»**: колонки «Заказ на производство» | статус | «Добавить»; строки существующих неотменённых PO нужного завода и «Новый PO» с выбором завода; поле с «+», без «Доступно».
   - **План** (~424px, sticky): весь план по всем товарам в той же группировке, в какой запуск создаёт документы. «Взять» — группа на место (WH-3, TR-311, OUT-208, PO-57…) со строками товаров; «Заказать дополнительно» — группа на PO / новый PO завода, количества с «+»; «Не покрыто». Строки выбранного товара подсвечены; клик по строке выбирает товар. Внизу «Сохранено · 18:42» и «Запустить» на всю ширину.
3. **Автосохранение** каждого ввода (debounce), кнопки «Сохранить» нет. Индикатор: «Сохраняется…» / «Сохранено · ЧЧ:ММ» / ошибка.
4. **Расхождения** считаются из живого состояния при открытии и после прямых действий: строка источника красная, «Доступно» красным, бейдж «−4»; источника больше нет — «−5» и чип «доехало» / «завершён»; лишнее — янтарный «Осталось −3». Те же строки подсвечены в блоке «План». «Запустить» недоступна, над ней одна строка «2 нехватки · 1 лишнее» (клик — к первой проблеме). Недоступна и у закрытого / отменённого заказа.
5. **Подтверждение запуска** — маленький диалог: «Запустить «План 2»?», «Это действие нельзя отменить.», «Отмена» / «Запустить». Больше ничего.
6. **Запущенный план** — только просмотр: числа вместо полей, у групп блока «План» ссылки-чипы на созданные документы (RSV-, OUT-, PO-), внизу «Копировать в новый черновик» и «В архив» (не дублировать в «⋯»). Расхождения не считаются.

Принцип, на котором настоял пользователь: **интерфейс понятен из формы, а не из текста**. Каждая строка на экране — имя, число, заголовок, чип или кнопка. Никаких поясняющих подписей вроде «при запуске — новый черновик выпуска под заказ» или «"+" недоступен: строка покрыта…». Недоступность видна из «Осталось 0» и приглушённых полей.

Не делать: даты готовности, согласования, заметки, автораспределение, сравнение планов, показ чужих планов на тот же остаток.

## Проверка перед сдачей

- `npm run lint`, `npm run typecheck`, `npm run build`, `npm run check:deps`, `npm run check:docs`, `npm run check:static-images`.
- В браузере на живом демо-бэкенде пройти: новый план → разложить товар из склада, пути, черновика выпуска, незанятого плана PO, докинуть в PO и новый PO → перезагрузить страницу (раскладка сохранилась) → вызвать расхождение прямым действием на карточке (подсветка, «Запустить» недоступна) → исправить → запустить → проверить созданные документы и ссылки, остатки без минуса → копировать запущенный план в черновик → архив и возврат.
- Все проверочные данные, созданные в демо-базе, удалить или вернуть.
- Закоммитить на локальный `main`, не пушить.
