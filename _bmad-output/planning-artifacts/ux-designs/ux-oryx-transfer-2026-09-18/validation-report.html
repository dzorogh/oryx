Accessibility & responsive review

review-accessibility-responsive.md

NEEDS REVISION. The accessibility floor is promising, but the contract is not implementation-ready for WCAG 2.2 AA or fully usable phone creation. Dirty-close and mobile-overflow blockers are consolidated under State coverage and Visual reference coverage above; this section preserves the reviewer's remaining adversarial findings.

high

Route errors are excluded from the error-focus contract

EXPERIENCE.md:81-89,93-113
Equal-warehouse errors can block creation, but focus and programmatic association are defined only for quantities.
Fix: Define one DOM-order validation sequence and require stable error ids, aria-invalid, aria-describedby, and first-invalid focus for every field.
high

Disabled actions conceal why progress is blocked

EXPERIENCE.md:69-75,81-89; direction-dense-ledger.html:199-203,235-238
Native disabled controls are not focusable, while the reference provides no persistent reason or path to completion.
Fix: Expose and politely announce a visible, associated blocking reason, including eligible-product exhaustion.
medium

Row removal can move focus to a disabled control

EXPERIENCE.md:73-74,93-101
The last-row fallback primary action cannot receive focus when disabled.
Fix: Use only adjacent controls, enabled Add product, or a focusable ledger heading/status as fallbacks.
medium

Ledger semantics and repeated-control names are incomplete

EXPERIENCE.md:103-113; direction-dense-ledger.html:191-199,229-234
Desktop and mobile rules do not fully bind product identity, unit, maxima, and errors to repeated quantity/remove controls. This consolidates A11Y-R06 and A11Y-R07.
Fix: Require a labeled native table on desktop and named list/groups on mobile with product-specific control names and described-by relationships.
medium

Reference target sizes contradict the 44×44 floor

EXPERIENCE.md:103-113; direction-dense-ledger.html:90-119,140-152
Inputs, buttons, remove, and close affordances are too small or undefined.
Fix: Guarantee a 44×44 CSS px hit area for every interactive target.
medium

Breakpoint changes preserve values but not focus identity

EXPERIENCE.md:115-122
A table/list remount can lose the active control or chooser focus.
Fix: Key controls by stable line id and define active-field and popover focus restoration during reflow.
medium

Zoom and reflow lack measurable acceptance criteria

DESIGN.md:100-105; EXPERIENCE.md:115-122
320 CSS px, 400% browser zoom, 200% text zoom, long names, and footer wrapping are untested contractually.
Fix: Add those cases and prohibit clipped required content and two-dimensional scrolling.
medium

Interactive and focus-indicator contrast is not locked down

DESIGN.md:78-87; direction-dense-ledger.html:90-103
Special text pairs pass, but controls and focus rings are unspecified; the reference remove glyph misses 3:1.
Fix: Record or test computed contrast for supported states and surfaces.
medium

Live regions can produce duplicate, noisy announcements

EXPERIENCE.md:66-75,103-113
Source changes can announce every row plus the issue summary.
Fix: Debounce one atomic summary, announce validity transitions, and suppress duplicates.
low

The visual direction can be mistaken for implementation markup

direction-dense-ledger.html:179-203,214-239
Generic elements, unnamed inputs, and non-button affordances can invite inaccessible copying.
Fix: Mark the artifact visual-only and require native shadcn primitives plus spine semantics.

Implementation feasibility review

review-implementation-feasibility.md

CONDITIONAL GO — not implementation-ready. Dense Ledger is buildable on current surfaces, but coding should not begin before the command, availability, allocation, integrity, and result contracts are explicit. F-04 is consolidated into the atomic API finding; F-12 is consolidated into Draft availability semantics.

critical

Atomic Draft creation and API result contract is missing

transfers-page.tsx:208-233; logistics-api.ts:705-744; run-action.ts:47-63
Separate browser writes cannot roll back, retries can duplicate partial Drafts, and the action path discards the id needed for detail navigation. This consolidates F-01 and F-04.
Fix: Define one transactional, idempotent create-Draft command returning a typed transfer-id result, then navigate only after commit.
critical

Draft availability semantics and line-error contract are unresolved

EXPERIENCE.md:142-153; docs/features/logistics.md:50-64
Draft creation does not claim stock, Send is authoritative, and the current generic error cannot identify affected rows. This consolidates F-02 and F-12.
Fix: Choose no check or advisory create-time validation, state that Draft does not reserve stock, and define structured per-line errors if validation remains.
high

Order entry still sends all reserved stock immediately

order-action-forms.tsx:695-724; logistics-api.ts:705-744
The current controller contradicts subset selection, editable quantities, and Draft-only creation.
Fix: Replace it with an order-context Draft controller using the atomic command.
high

“Order-line allocation” is not a persisted identity

EXPERIENCE.md:39,70-72,144-153; migration:116-123,180-193
Persistence records owner plus product, not an immutable order-line id; the wording depends on product uniqueness within an order.
Fix: State the UI-key versus persisted-identity boundary and document the order+product uniqueness dependency.
high

Duplicate-product integrity is guarded only in the client

transfers-page.tsx:105-112,181-188; migration:896-899
Direct, retry, or concurrent requests can create duplicates while completion selects an arbitrary matching line.
Fix: Validate in the RPC and add a unique (transfer_id, product_id) constraint unless duplicates are intentional.
high

On hand and Available have no executable formulas

DESIGN.md:99-128; EXPERIENCE.md:70-72; docs/features/logistics.md:34-47
Physical, free, and owner-specific balances can yield several plausible implementations.
Fix: Define On hand across all physical source balances, generic Available as free/null-owner, order Available as current-order reserved, and state that Drafts reduce neither.
medium

Eligibility and source-change row policy is underspecified

EXPERIENCE.md:66,70,81-86; transfers-page.tsx:180-181,665-678
Pre-source choices, now-ineligible rows, and Add product exhaustion are not deterministic.
Fix: Gate choice on source, filter eligible products, preserve and invalidate stale rows inline, and derive Add product from remaining choices.
medium

Shared presentation risks shared inventory logic

EXPERIENCE.md:15-29; transfers-page.tsx:76-93,637-715
Generic free stock and order-owned reserved stock have incompatible rules.
Fix: Share presentation primitives but use separate context adapters mapped to one command.
medium

Pending-state guard is absent

EXPERIENCE.md:74,88; transfers-page.tsx:333-335; run-action.ts:47-63
Double click or Enter-plus-click can submit concurrently; server retry idempotency belongs to the critical command contract.
Fix: Add a synchronous controller guard and visible pending state.
medium

Entry eligibility contradicts loading and empty-state rules

EXPERIENCE.md:80-82; transfers-page.tsx:170-178,237-260; customer-orders-page.tsx:367-379
Launchers can open while data is unavailable or no eligible order-owned stock exists.
Fix: Gate the list launcher on load state and derive order eligibility before opening, with an explanation at the launcher.
