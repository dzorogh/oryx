topic: Операционная модель бронирования и снятия брони
updated: 2026-09-18T02:04

- (direction) Источник: brainstorm-intent; цель — один подход без дублирующих документов снятия и сторно
- (decision) Модель операционная: posted RSV и REL неизменяемы; бизнес-отмена = новый posted REL
- (decision) Сторно для reservation и reservation_release исключено; cancel RPC для этих kind отклоняется
- (decision) REL не ссылается на RSV; ссылается на заказ, строку заказа, место, тип остатка и количество
- (capability) CAP-1 Оператор проводит RSV и переводит free в reserved под заказ в пределах свободного остатка и открытой потребности
- (capability) CAP-2 Оператор проводит REL и переводит reserved заказа обратно в free в пределах фактического резерва места
- (capability) CAP-3 Перемещение сохраняет тип остатка и заказ; не отменяет бронь и не пишет сторно RSV
- (capability) CAP-4 Отгрузка уменьшает складской reserved и увеличивает shipped в заказе; REL после этого освобождает только оставшийся reserved
- (capability) CAP-5 UI и API не предлагают сторно posted RSV/REL; единственный путь освободить резерв — REL
- (constraint) Учёт только qty SKU без партий и серий
- (constraint) Нельзя забронировать больше free на месте или больше remainingToReserve строки заказа
- (constraint) Нельзя снять больше reserved выбранного ключа (место + заказ + строка)
- (constraint) Нельзя переместить больше доступного остатка выбранного типа
- (constraint) Один заказ может иметь несколько активных RSV одного SKU; резерв одной строки может лежать на нескольких местах
- (constraint) Журнал logistics_stock_transaction остаётся источником остатков; posted RSV/REL пишут движения и больше не реверсируются
- (assumption) Существующие таблицы RSV/REL, журнал и RPC post_* сохраняются; меняется запрет cancel/reverse для этих kind
- (assumption) Сторно shipment/transfer/return/output вне этой спецификации, кроме запрета использовать их вместо REL
- (assumption) Закрытие заказа по-прежнему создаёт posted REL на фактический reserved, а не reverse RSV
- (constraint) Исторические cancelled RSV/REL могут остаться в БД как архив; новые cancel для этих kind запрещены
- (decision) Non-goals: партии/серии; частичное снятие как отдельный тип документа; статус cancelled как рабочий путь RSV/REL; сторно как undo брони; производство сырья
- (event) Self-validate pass 1 (coherence): CAP-1..5 have intent+success; constraints bend design; non-goals present; success signal testable; IDs stable; prose lean
- (event) Self-validate pass 2 (preservation): intent claims landed in SPEC + operational-model + brownfield; wrapper chronology dropped
- (event) Architecture spine adopted as companion
- (decision) SPEC обновлён: RSV и REL слиты в одну Reservation с operation reserve|release
- (capability) CAP-6 Одна сущность, один RSV-код, один список и один posting RPC для обоих направлений
