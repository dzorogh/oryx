# Правила денег заказа

Одни и те же для заказа на производство (PO) и заказа клиента.

## Снимок курсов

- Курс `rate` — сколько единиц валюты за 1 USD, `inverse_rate` = 1 / `rate`. Формат floatrates: `https://www.floatrates.com/daily/usd.json` → `{code, rate, inverseRate, date}` (146 валют, CORS `*`).
- При создании заказа снимок включает все валюты `store_currency` (как `OrderCurrencyService::snapshotCurrencies` в my-back). USD = 1.
- Браузер получает курсы при открытии окна создания и передаёт их в RPC создания. Они же обновляют `store_currency.rate`. Если API недоступен, RPC берёт `store_currency.rate`.
- Ручная правка курса в заказе пишет снимок той же командой, что и создание. `rate` > 0.

## Конвертация

`convert(amount, from, to) = amount / rate[from] * rate[to]` по снимку заказа. Если `from = to`, сумма не меняется.

## Суммы

- **Расчётная стоимость** = Σ по строкам `convert(unit_price × quantity, line.currency, order.currency)`.
  - Для PO цена — закупочная, для заказа клиента — дилерская региона. Обе уже пишутся в строку снимком.
  - Строка без `unit_price` даёт 0, без пометки.
- **Сумма заказа** — необязательное поле в валюте заказа. Если пусто, берётся расчётная стоимость.
- **Не распределено по платежам** = сумма заказа − Σ сумм всех платежей заказа (включая оплаченные).
  - Отрицательное значение подсвечивается только в карточке заказа. В календаре заказ вносит `max(0, …)`.
- **Смена валюты заказа** не пересчитывает числа суммы заказа и платежей, меняется только их валюта. Расчётная стоимость пересчитывается по снимку в новую валюту.

## Платёж

| Поле | Правило |
|---|---|
| Срок оплаты | дата, обязательна |
| Сумма | > 0, в валюте заказа |
| Статус | вручную: `planned` «Запланирован» → `invoiced` «Выставлен счёт» → `paid` «Оплачен»; разрешён любой переход |
| Просрочка | вычисляется: срок < сегодня и статус ≠ `paid` |

- У заказа клиента те же поля. Смысл — входящая оплата от клиента.
- Отмена заказа не меняет статусы платежей: они просто не показываются в календаре.
