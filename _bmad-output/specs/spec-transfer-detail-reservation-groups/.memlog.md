- (decision) Express mode: UX discovery complete; distill directly without further elicitation.
- (capability) CAP-1: Transfer detail exposes one clear document header with identity, status, expected date, actions, and a single origin-current-destination route; success is unambiguous in all lifecycle states.
- (capability) CAP-2: Product quantities are grouped by owner by default into Free, each Order, and each Region; success means split products repeat in every positive owner group with exact bucket quantity and group totals.
- (capability) CAP-3: User can disable grouping to see one product row with total and expand exact Free/Order/Region breakdown; success means breakdown sums equal total and owner labels include order number or region code plus name.
- (capability) CAP-4: Product manifest and chronological document activity use a useful 2fr/1fr desktop composition and stack responsively; success means 15+ products remain dense without an empty center.
- (capability) CAP-5: In-transit free stock can launch the existing auditable Reservation flow at the current transfer location from one page-level action; success means reload updates owner groups and activity without optimistic split.
- (capability) CAP-6: Draft, sent, delivered, cancelled, loading, error, not-found, and empty states remain usable and accessible; success is testable against the UX state and accessibility contracts.
- (constraint) Use existing order/region owner, balances, immutable transactions, ReservationForm, Oryx shadcn/Tailwind shell, and English UI labels; no backend schema or silent allocation mechanism.
- (constraint) Full-width page root remains; route/status facts appear once; no helper cards, wide sparse quantity columns, per-row reserve actions, or explanatory reservation prose.
- (constraint) Implementation must preserve current draft line editing and lifecycle mutations and must add focused unit/component coverage before full project verification.
- (decision) Adopt finalized UX DESIGN.md and EXPERIENCE.md as downstream companions; add brownfield.md for implementation context.
- (decision) Non-goals: transfer list, new-transfer dialog, backend migrations, partial receiving, new reservation semantics, unrelated logistics redesign.
- (assumption) Grouping is local view state, enabled on each fresh page entry; it does not persist to URL or backend.
