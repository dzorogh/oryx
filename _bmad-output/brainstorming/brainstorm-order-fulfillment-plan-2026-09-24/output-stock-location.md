# Выпуск как место количества

Решение сессии 24.09.2026: у выпуска появляется своё место в `store_stock_location`, как у склада, перемещения, заказа на производство и заказа клиента. Тогда любое количество — в журнале, в черновике выпуска, в незанятом плане заказа на производство и в действии плана — описывается одной парой «место × владелец».

## Почему место, а не владелец

Владелец отвечает «кому обещано»: свободно, регион, заказ клиента. В одном черновике выпуска одновременно лежит количество разных владельцев (строки с разными `to_owner_id`). Если сделать выпуск владельцем, пропадёт, под кого это количество. Выпуск отвечает «где будет количество», как склад или перемещение в пути, только будущее.

## Модель

| Место | Вид в `store_stock_location` | Откуда берётся количество по паре «место × владелец» | Проводки в журнале |
|-------|------------------------------|-------------------------------------------------------|--------------------|
| Склад | `warehouse` | `store_stock_balance` | Да |
| В пути | `transfer` | `store_stock_balance` | Да |
| Отгружено клиенту | `customer_order` | `store_stock_balance` | Да |
| Черновик выпуска | `production_output` (новый) | Сумма строк выпуска со статусом `draft` по `to_owner_id` | Нет |
| Незанятый план заказа на производство | `production_order` (есть) | Только владелец «свободно»: план − строки неотменённых выпусков | Нет |

Выпуск `done` и `cancelled` сохраняет своё место, но источником оно больше не является: количество 0. Для плана это «источника нет». Товар завершённого выпуска лежит на складе завода, там его проводки.

Заказ на производство `done` / `cancelled`: незанятый план = 0 (закрытие отменяет черновики выпусков, а остаток плана уже не будет произведён). Докинуть в закрытый заказ на производство можно: добавленное сразу становится черновиком выпуска — источником становится этот выпуск, а не заказ на производство.

## Решения, которые нужно подтвердить

| # | Решение | Рекомендация |
|---|---------|--------------|
| D-1 | Пишем ли проводки на место выпуска | **Нет.** Журнал хранит только физические факты. Место выпуска — ключ, количество считается из строк, как у заказа на производство сегодня. Проводки появятся только при завершении выпуска, на складе завода, как сейчас. |
| D-2 | Незанятый план закрытого заказа на производство — источник? | **Нет** (см. выше). |
| D-3 | Что делать с четырьмя выпусками `in_progress` при удалении статуса | Перевести в `draft` (количество ещё не на складе). Решает владелец изменения. |

## Единая функция доступного количества

`store_place_available(p_variant_id, p_location_id, p_owner_id) returns numeric` — одна функция для чтения, проверки ввода и запуска:

- `warehouse`, `transfer` → `store_qty(variant, location, owner)`;
- `production_output` → сумма `quantity` строк выпуска с этим `to_owner_id`, если выпуск `draft`, иначе 0;
- `production_order` → при владельце «свободно» и статусе не `done` / `cancelled`: `store_po_plan_qty − store_po_output_qty`, иначе 0;
- `customer_order` → 0 (отгруженное не источник).

Блокировка одинаковая для всех мест: advisory lock по `(variant, location, owner)` через `store_lock_stock_keys`, плюс `FOR UPDATE` строк выпуска и заказа на производство там, где они меняются.

## Изменения в базе

1. `store_stock_location.kind`: CHECK добавляет `production_output`; обновить комментарии таблицы и колонки.
2. `store_production_output.stock_location_id bigint not null unique references store_stock_location (id)`, комментарий.
3. Миграция: создать место каждому существующему выпуску (в живой базе 23), затем `NOT NULL`.
4. `store_create_production_output`: создаёт место `store_new_stock_location('production_output')`.
5. `store_move_in_production_output`: добавить advisory locks по обоим ключам «место выпуска × владелец» — чтобы запуск плана и прямые действия сериализовались одинаково.
6. `store_create_and_post_reservation`: место `production_output` запрещено с тем же текстом «Резервируйте в выпуске заказа на производство».
7. `store_location_ref`: `union all select o.stock_location_id, 'production_output', o.id from store_production_output o`; комментарий.
8. `store_context_payload` / `store_document_context`: отдавать `stock_location_id` выпусков.
9. Комментарий `store_production_order.stock_location_id`: «место незанятого плана (владелец свободно), без проводок» вместо «для нескладских назначений резерва».
10. `store_stock_balance_ref`, `store_stock_page`, `store_ledger_page`, календарь: не меняются — проводок на новом месте нет.

## Изменения в приложении

- `LOCATION_KINDS` / `LocationKind` + `production_output`.
- `LOCATION_LABELS` и `locationKindLabel`: «Выпуск».
- `resolveStockLocationId`: читать `store_production_output.stock_location_id`.
- `hrefForLocation`, `logistics-lookups` (switch по виду места): ветка на карточку выпуска.
- `logistics-balances` (`Record<LocationType, number>` через `LOCATION_TYPES`) — ключ появится сам; проверить подписи.
- Фильтры вида места на «Остатках» и в «Журнале»: выпуск не показывать — проводок нет.
- Тип `ProductionOutput`: поле `stockLocationId`.

Действие плана хранит одну пару `location_id` × `owner_id` для любого источника; `source_document_id` не нужен. Новое производство — `plant_id`.
